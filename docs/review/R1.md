## Style agreement of the five files
- Error output: clone_car `error: ...` on stderr, rc=1 (matches car_json/tune/tuner_server); kspkg, pb_raw, dump_car, extract_protos: raw tracebacks. extract_protos self-check failure uses `sys.exit("self-check FAILED: ...")` (stderr, rc=1): consistent with the convention except for the wording.
- Warnings/notes: clone_car prints "note: ..." on stdout (tune relies on that), no "warning:" in these files.
- Encodings: utf-8 explicit everywhere; no BOM written; no mixed-language messages (all English).
- Exit codes: kspkg unknown command 2, clone_car usage 1, verify difference 1.
- Paths: kspkg/clone_car use os.path with long_path; dump_car/extract_protos/pb_raw use pathlib without long_path.
- Magic numbers: 0xE0 (kspkg 155), 0xE4/0xE6/0xE8 offsets in read_table and pack are documented in the docstring and appear in two places each (read 82-83, write 177): consistent, no finding. `1 << 20` appears as HEADER and again as literal at kspkg.py:168 (`pad = (-off) % (1 << 20)`): could use HEADER (cosmetic, same value, different meaning: alignment vs header size).
- Usage text vs argv: kspkg docstring matches argv (no count checks); clone_car usage matches implemented options (all 8 options + --no-pack implemented; defaults of --year/--brand undocumented -> R1-024); extract_protos/dump_car usage match.
