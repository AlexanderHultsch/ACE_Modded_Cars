## 4. How EVO loads mod cars

- One `.kspkg` per car directly in `%USERPROFILE%\Saved Games\ACE\mods\` (the folder did not exist before the first install; `Saved Games\ACE` holds the game's settings and `Logs`).
- Registration: a mod car needs `content\cars\<id>\<id>.moddedcarcontent` (message `ModdedCarContentData`: display_name, brand, year, property_1/2/3, sub_categories). The stock E46 has none (stock cars are in the game's own tables).
- Names in the selection screen come from localization keys `<id>_<preset description>`; for a mod they are found in `content\cars\<id>\uiresources\localization\en.cars.loc` (inside the package; CRLF, UTF-8, no BOM). Without it the raw keys are shown.
- `data/<id>.car` is the manifest (fields such as `stock_setup`, `setupLimits`, engine/drivetrain/gearbox paths) and also embeds inline copies of engine, gearbox, drivetrain, brakes etc. Which copy the game reads is unknown; the tuner writes both.
- Cars need no patching of the game's `content.kspkg`. Mod cars may reference stock assets and data by path.
- The clone approach: copy the extracted stock car, replace the id everywhere by a same-length id (`ks_bmw_m3_e46_csl` -> `ax_bmw_m3_e46_csl`) in names and file contents, so no protobuf length changes; add registration and localization; pack. The id also appears inside `.mesh`, `.actor`, `.car` and other files.
- Online: since 0.8.1 servers reject mods not re-exported through the SDK. Single-player only.
- A Kunos modding skeleton `ks_modded_car` exists (used by EvoForge and the Daytona example).

## 5. .kspkg format

Verified on HDC, example mods, `sdk.kspkg` and the game's `content.kspkg`. The game reads strictly through the table.

```
[0, 0x100000)          1 MiB header, all zero (not present in every package)
[0x100000, data_end)   file data, contiguous, largest file first in HDC-style packages
[size-64MiB, size)     file table: 256-byte entries sorted ascending by hash, rest zero.
                       Whole 64 MiB XOR'd with 8-byte key c135117da921979f (repeating from table start)
entry +0x00  path, utf8, backslashes, <= 0xE0 bytes, zero padded
      +0xE4  int16 flags: 1 = directory, 0x100 = file data XOR'd with the same key (repeating from file start)
      +0xE6  int16 path length
      +0xE8  uint64 hash = FNV-1a 64 over the LOWER-CASE path encoded as UTF-16LE
      +0xF0  int64 size, +0xF8 int64 offset (directories: 0)
```

Game package: every file is XOR-flagged. Mods vary (Nissan example: 572 of 783 flagged, no header, mixed-case paths). `pack` writes flag 0 and lower-case paths; the game accepted such a package (the clone loads). Pre-0.7 tools (`ntpopgetdope/ace-kspkg`) assume a 32 MiB table.

## 6. Schemas and tools

- `python tools/extract_protos.py "<...>\Assetto Corsa EVO SDK\AssettoCorsaEVOEditor.exe" schemas` -> `schemas/acevo.desc` + `.proto` files. The Editor and the game contain the same car schemas.
- `python tools/car_json.py decode|encode|check|types`. JSON keys are schema names in wire order, present only if present on the wire (absent = proto3 default, an empty message is `{}`), enums by name, floats shortest-for-float32, reserved keys `_order`, `_packed`, `_unknown`. Fields unknown to the schema and wire-type conflicts are kept untouched in `_unknown` (conflicts with a `mismatch` key). `encode` accepts a UTF-8 BOM.
- The real game files contain "legacy tail" fields beyond the schema (for example a second gear set and old autoshift values in `.drivetrain`, foreign car names such as the Alfa Giulia in `.clutch`/`.drivetrain`). They are preserved but not named. Not mapped: `.actor` (string field holds non-UTF-8 data), `.turbo`, `.cardisplaysystem`, `.carwipersystem`, `.tyre`, `.tyremesh`.
- Do not use `Nenkai/ACEvo.Package` (its AGENTS.md prohibits use by AI tools). `Breakalien/ac-evo-data-tools` and `Seigneur-Machiavel/AC_EVO_Modding` are references.

## 7. Field knowledge (real names, real E46 values)

Full list with defaults and descriptions: docs/BMW_SETTINGS.md. Highlights:
- Engine (`EngineData`): limiter 8100, minimum (idle) 700, nominal_rpm 8100, damage.rpmDamageThreshold 7700, limiterCycles 30, inertia 0.22, throttle lag 0.98 / 0.97 (the map entry has its own lag values), power curve peak 360 (curve points `{rpm, value}`; torque is field `value`).
- Gearbox (`GearBoxData`): 6 gears 4.227 / 2.528 / 1.669 / 1.226 / 1.0 / 0.828, reverse -3.746, final 3.62, autoshift up 7900. The `.drivetrain` carries an older second set (4.055 ... final 3.09) outside the schema; the schema-known set is the one in `.gearbox`.
- Differential: hardware in drivetrain `differential_data` (`type` enum LSD / Spool / Torsen / EpicyclicTorsen / EpicyclicLSD / TorqueVectoring; stock has no type = LSD; preload 1.0, torque bias 2.3 / 0.5), the in-game setup default in `.carsetup` `mechanical_balance.differential` {power 0.3, coast 0.1, preload 10} and the offered range in `.carsetuplimits` (power max 0.1, coast max 0.1, preload max 10: below the default, unexplained).
- Setup (`CarSetupData`): steer_ratio 14.5, brakes.front_bias 63, arbs 70000 / 50000, wheel_rate 80000 front / 65000 rear, dampers per wheel, alignments (camber -2.0 / -1.5, toe -0.01 / 0.15, pressure 27), fuel 30. Wheel order FL, FR, RL, RR.
- Hardware: handBrakeTorque 1100, brake totalTorque 3700, controls.steer_lock 540, general.totalMass 1495 (the preview spec sheet shows 1460 kg: display text).
- Mechanical preset car_specs (power 360, torque 370, ...) is display text only, independent of physics.
- Game log: `Creating car: <id>` and `POWER CLASS INDEX: ... (357.18982 HP) W:1517.65` in `Saved Games\ACE\Logs\log-*.txt` is the physics view of the car and verifies power/mass edits without driving.
